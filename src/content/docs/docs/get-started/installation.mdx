Install Arcane to manage Docker on your host through a single container. Use Docker Compose, or run the Linux install script to set up both Docker and Arcane.

> [!NOTE]
> To manage other hosts later, add [remote environments](/docs/remote/environments). To restrict Docker socket access, use a [socket proxy](/docs/security/socket-proxy).

<Tabs syncKey="install-method">

<TabItem label="Docker">

## 1. Generate an encryption key

Generate a 32-byte `ARCANE_ENCRYPTION_KEY` (raw, base64, or hex) with one of these commands and copy the output.

With a temporary Arcane container:

```bash
docker run --rm ghcr.io/getarcaneapp/manager:latest /app/arcane generate secret
```

With the Arcane CLI:

```bash
arcane-cli generate secret
```

With OpenSSL:

```bash
openssl rand -hex 32
```

> [!NOTE]
> Arcane signs session tokens with a self-managed ML-DSA-87 key instead of `JWT_SECRET`. Remove `JWT_SECRET` from your environment to silence startup warnings.

## 2. Create `compose.yaml`

Replace `<your-encryption-key>` with your key and `/opt/docker` with the folder for your Compose projects:

```yaml
services:
  arcane:
    image: ghcr.io/getarcaneapp/manager:latest
    container_name: arcane
    ports:
      - '3552:3552'
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - arcane-data:/app/data
      - /opt/docker:/opt/docker
    environment:
      - ARCANE_APP_URL=http://localhost:3552
      - PUID=1000
      - PGID=1000
      - ARCANE_ENCRYPTION_KEY=<your-encryption-key>
      - ARCANE_PROJECTS_DIRECTORY=/opt/docker
    cgroup: host
    restart: unless-stopped

volumes:
  arcane-data:
```

> [!NOTE]
> The official images start as root to prepare the container, then drop to a non-root user. `PUID` and `PGID` set the host UID and GID for files Arcane creates, or default to `65532:65532` if omitted.

### Projects folder

> [!IMPORTANT]
> Mount your projects folder at the same absolute path inside the container (such as `/opt/docker`, not `opt/docker`) and set `ARCANE_PROJECTS_DIRECTORY` to match. Matching paths let relative mounts like `./config` resolve identically for Arcane and Docker, and let Arcane manage existing projects in that folder.

If you mount a different container path (such as `/opt/docker:/app/data/projects`), Arcane translates container paths to host paths automatically. You can also set the mapping explicitly with `ARCANE_PROJECTS_DIRECTORY=<containerPath>:<hostPath>`. If omitted, `ARCANE_PROJECTS_DIRECTORY` defaults to `/app/data/projects`.

## 3. Start Arcane

```bash
docker compose up -d
```

## Run the install script

Run the Linux install script to install Docker and Arcane:

```bash
curl -fsSL https://getarcane.app/install.sh | sudo bash
```

### Uninstall

Run the interactive uninstaller to choose whether to keep Arcane data, the Arcane user and group, and Docker:

```bash
curl -fsSL https://getarcane.app/uninstall.sh -o /tmp/arcane-uninstall.sh && sudo bash /tmp/arcane-uninstall.sh
```

To remove everything without prompting:

> [!WARNING]
> This removes Arcane, its data, the Arcane user and group, and Docker packages. Run it only if you want to remove Docker from the machine too.

```bash
curl -fsSL https://getarcane.app/uninstall.sh | sudo bash -s -- --force --remove-all
```

## Open Arcane

Open [localhost:3552](http://localhost:3552), sign in with the default credentials, and set a new password when prompted.

Username:

```bash
arcane
```

Password:

```bash
arcane-admin
```

## More setup options

Expand any section that applies to your environment.

<Collapsible id="folders-and-volumes" title="Folders and volumes" description="What each mount is for, plus optional build and backup folders.">

| Mount                  | Purpose                                                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| `/var/run/docker.sock` | Connects Arcane to Docker. Use a [socket proxy](/docs/security/socket-proxy) to restrict access.           |
| `arcane-data`          | Stores Arcane's database and application data.                                                             |
| Projects folder        | Holds your Compose projects. See [Projects folder](#projects-folder).                                      |
| `/builds`              | Optional. Stores Dockerfiles and build contexts for [Image Builds](/docs/docker/image-builds).             |
| `/backups`             | Optional. Stores exported volume [Backups](/docs/docker/backups).                                          |

> [!TIP]
> To use the optional folders, add them to `volumes:` in your `compose.yaml`:
>
> - `/builds` — host path `/srv/arcane/builds:/builds` or named volume `arcane-builds:/builds`.
> - `/backups` — host path `/srv/arcane/backups:/backups` or named volume `arcane-backups:/backups`.
>
> Declare any named Docker volumes under the top-level `volumes:` section too.

</Collapsible>

<Collapsible id="selinux-hosts" title="SELinux hosts" description="Use a socket proxy or relabel the Docker socket mount.">

On SELinux hosts, choose one of two options:

- **Use a socket proxy (recommended).** Run a proxy, set `DOCKER_HOST`, and add `:z` to the projects mount (`/opt/docker:/opt/docker:z`). See [Socket Proxy](/docs/security/socket-proxy).
- **Mount the socket directly.** Disable SELinux labeling on the Arcane container and relabel the projects mount:

```yaml
services:
  arcane:
    image: ghcr.io/getarcaneapp/manager:latest
    container_name: arcane
    ports:
      - '3552:3552'
    security_opt:
      - label:disable
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - arcane-data:/app/data
      - /opt/docker:/opt/docker:z
    environment:
      - ARCANE_PROJECTS_DIRECTORY=/opt/docker
```

</Collapsible>

<Collapsible id="container-health-check" title="Container health check" description="Add a Docker health check using the built-in arcane health command.">

Add a Docker health check using the built-in `arcane health` command, which checks `/api/health`:

```yaml
services:
  arcane:
    image: ghcr.io/getarcaneapp/manager:latest
    # ...
    healthcheck:
      test: ['CMD', './arcane', 'health', '--timeout', '2s']
      interval: 10s
      timeout: 3s
      retries: 5
      start_period: 15s
```

`start_period` gives Arcane time to finish first-boot database migrations before failed checks count toward `retries`.

</Collapsible>

<Collapsible id="external-postgres" title="External Postgres database" description="Store Arcane's data in Postgres instead of the built-in SQLite file.">

Set `ARCANE_DATABASE_URL` to store Arcane's data in Postgres instead of the default SQLite file in `arcane-data`:

```bash
postgres://<db_username>:<db_password>@<postgres_url>:<postgres_port>/<postgres_db_name>
```

To switch back to the default SQLite database, set:

```bash
file:data/arcane.db?_pragma=journal_mode(WAL)&_pragma=busy_timeout(2500)&_txlock=immediate
```

</Collapsible>

<Collapsible id="supported-architectures" title="Supported architectures" description="CPU architectures available for the images and binaries.">

Docker automatically pulls the matching `manager` or `agent` image for:

- `linux/amd64`
- `linux/arm64`
- `linux/arm/v7`
- `linux/riscv64`

CLI and agent binaries on [GitHub Releases](https://github.com/getarcaneapp/arcane/releases/latest) also support Linux `386` and macOS (`amd64`, `arm64`).

</Collapsible>
