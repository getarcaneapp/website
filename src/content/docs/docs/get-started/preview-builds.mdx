Run preview builds (also called `next` builds) on a test instance to try new features or verify fixes from the `main` branch before a stable release.

> [!CAUTION]
> Preview builds may contain bugs, unfinished features, or breaking changes. Do not run them in production.

## Use a preview build

1. Change the image tag in your `compose.yaml` to `next`.

Manager:

```bash
ghcr.io/getarcaneapp/manager:next
```

Agent:

```bash
ghcr.io/getarcaneapp/agent:next
```

Example `compose.yaml`:

```yaml
services:
  arcane:
    image: ghcr.io/getarcaneapp/manager:next
    container_name: arcane
    ports:
      - '3552:3552'
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - arcane-data:/app/data
    environment:
      - ARCANE_APP_URL=http://localhost:3552
      - ARCANE_ENCRYPTION_KEY=<your-encryption-key>
    restart: unless-stopped

volumes:
  arcane-data:
```

2. Recreate the container:

```bash
docker compose up -d
```

> [!TIP]
> Pin a specific preview build with its versioned tag, such as `ghcr.io/getarcaneapp/manager:v2.4.0-next.1`.

## Switch off development branding

Non-release builds (any version other than a plain release like `v2.4.0`) display a development icon for the logo, favicon, and app icons. To restore the standard logo, click the version number at the bottom of the sidebar and turn off **Development Branding** (requires `settings:write`).

## Report a problem

Open an issue on [GitHub Issues](https://github.com/getarcaneapp/arcane/issues) and include the version number shown on your dashboard.

## Image tags

Preview images run static binaries on Arcane's distroless base image (a minimal image without a shell or package manager).

| Tag                        | Points to                                         |
| -------------------------- | ------------------------------------------------- |
| `next`                     | The latest build from `main`.                     |
| `next-static`              | Alias for `next`, kept for existing setups.       |
| Versioned, `v2.4.0-next.1` | That specific build (`v2.4.0-next.1`, `.2`, etc.). |
