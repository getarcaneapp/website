## Settings overrides

- An invalid value stops Arcane at startup.
- `ARCANE_UI_CONFIGURATION_DISABLED=true` makes every setting read-only in the UI.

## Container runtime user

Set `PUID` and `PGID` to make mounted files belong to a specific host user and group.

Without them, Arcane drops to its built-in non-root user (`65532:65532`) inside a container. Outside a container, it keeps the user it started as.

Arcane treats itself as containerized when any of these is true:

- `ARCANE_IN_CONTAINER=true` (the official images set this).
- The `container` variable is non-empty.
- `/.dockerenv` or `/run/.containerenv` exists.

If `DOCKER_HOST` points at a custom Unix socket, Arcane adds the runtime user to that socket's group.

## Timezone and scheduled jobs

Set `TZ` to an [IANA timezone name](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones) so recurring jobs run on your local time:

```bash
TZ=America/New_York
```

This covers image update checks, auto-updates, vulnerability scans, scheduled pruning, GitOps sync, and environment health checks. Without `TZ`, Arcane uses the container's local time (UTC on the official images). Schedule dialogs show the timezone in use.

Set job intervals and cron expressions in the Settings UI or with [settings overrides](#settings-overrides).

## Default admin account

On first start with an empty database, Arcane creates an admin named `arcane` with a random password, writes the password to `/app/data/initial-admin-password`, and asks for a new password at first sign-in. These variables change that. They are read only when the admin is created, so they never change an existing account.

| Variable                        | Default  | Description                                                                                       |
| ------------------------------- | -------- | ------------------------------------------------------------------------------------------------- |
| `ARCANE_DEFAULT_ADMIN_USERNAME` | `arcane` | Username of the admin created on first start.                                                     |
| `ARCANE_DEFAULT_ADMIN_PASSWORD` | Random   | Password of that admin. To read it from a file, set `ARCANE_DEFAULT_ADMIN_PASSWORD_FILE` instead. |
| `ARCANE_DEFAULT_ADMIN_DISABLED` | `false`  | Set to `true` to create no default admin.                                                         |

A password you set is not written to that file, and Arcane does not ask you to change it. It must meet the [password policy](/docs/access/account-recovery#password-policy); otherwise Arcane logs a warning and creates no admin until you fix the value and restart.

```yaml
services:
  arcane:
    environment:
      - ARCANE_DEFAULT_ADMIN_USERNAME=ops-admin
      - ARCANE_DEFAULT_ADMIN_PASSWORD_FILE=/run/secrets/arcane_admin_password
    secrets:
      - arcane_admin_password

secrets:
  arcane_admin_password:
    file: ./secrets/arcane_admin_password.txt
```

> [!WARNING]
> With `ARCANE_DEFAULT_ADMIN_DISABLED=true`, nobody can sign in until [SSO](/docs/access/sso) is configured from the environment and maps a user to the Admin role.

## Admin API key and observability

Set `ARCANE_ADMIN_STATIC_API_KEY` when automation needs a known API key from first start. At startup, Arcane creates or updates a protected admin API key with this value. The key belongs to the [default admin](#default-admin-account). See the [API Reference](/docs/reference/api) for examples.

Set the standard `OTEL_*` exporter variables to export metrics, traces, and logs. See [OpenTelemetry](/docs/settings/opentelemetry).
