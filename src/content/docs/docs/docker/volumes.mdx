Docker volumes hold data that outlives a container, such as databases and uploads.

## Create a volume

1. Open **Volumes** and click **Create Volume**.
2. Enter a name.
3. Optional: pick a driver or add labels.
4. Click **Create**.

## Browse volumes

Open **Volumes** in the sidebar. The table shows each volume's name, driver, and current usage.

## Rename a volume

1. Make sure no container is using the volume.
2. Open the row's dropdown and choose rename.
3. Enter the new name. Arcane copies the data to a volume with that name, then removes the original.

> [!NOTE]
> Renaming a volume that a project manages doesn't update the project. Change the volume name in the project's configuration too, or the next deploy may recreate the original volume.

## Remove a volume

1. Open the row's dropdown and click the trash icon.
2. Confirm.

Volumes used by a container can't be removed.

## Volume Workspace

The workspace lets you work with a volume's files while containers keep running.

1. Open a volume's **Workspace**.
2. Edit, add, or move files (see the table below).
3. Click **Save**. Edits are staged locally and applied together.

If a file you edited changed in the volume since you opened it, the save is rejected. Refresh, then reapply your edits.

| Action                           | What it does                                                       |
| -------------------------------- | ------------------------------------------------------------------ |
| Open a file                      | Edit any UTF-8 text file in a tab.                                 |
| **New File** / **New Folder**    | Create files and folders anywhere in the volume.                   |
| **Upload Files**                 | Add files from your computer. Asks before replacing existing ones. |
| **Download**                     | Save any file, including binary files, to your computer.           |
| **Rename**, **Move**, **Delete** | Reorganize the contents.                                           |
| Restore a file                   | Restore a single file from an existing volume backup.              |

Limits:

- Binary files, symlinks, and special files are read-only in the editor. Binary files can still be uploaded, downloaded, and moved.
- Files over the maximum size (default 10 MiB) can't be edited in place.
- The tree loads a folder's contents when you open it. A folder with more entries than the entry limit shows only its first entries. The workspace tells you when that happens.
- Volumes with a custom mount configuration (bind-style driver options) can't be opened in the workspace.
- If the container sets a numeric `user:`, workspace writes use that user and group instead of root.

Set the limits on the Arcane container:

| Variable                                   | Default |
| ------------------------------------------ | ------- |
| `ARCANE_VOLUME_WORKSPACE_MAX_FILE_SIZE_MB` | `10`    |
| `ARCANE_VOLUME_WORKSPACE_MAX_ENTRIES`      | `10000` |

Browsing and downloading need `volumes:read`. For write actions, see the [permission catalog](/docs/access/roles#permission-catalog). Roles and API keys with the legacy `volumes:browse` permission migrate to `volumes:read` automatically.

## Back up and restore

Open a volume's **Backups** to create or schedule snapshots on local storage or S3, or to restore data.

- [Backups](/docs/docker/backups) covers setup and recovery.
- [System-managed volume backups](/docs/docker/backups#system-managed-volume-backups) covers scheduling several volumes together.

## Helper containers

Arcane creates helper containers for backup, restore, and workspace access.

- They carry the label `com.getarcaneapp.internal.resource=true` and are hidden from the Containers list by default. To see them, turn on **Show Internal Containers** in the container table's view options.
- Backups and restores run in short-lived containers using Rustic, the backup tool behind [Backups](/docs/docker/backups).
- The workspace helper keeps the volume mounted between operations, so it doesn't restart each time you browse.
- Arcane removes the workspace helper after the **Volume Helper Idle Timeout** (default 10 minutes). Set it to `0` to turn off idle cleanup.
