## Create a container

1. Open **Containers** and click **Create Container**.
2. Enter a name and an image. Ports, volumes, environment variables, restart policy, and other fields are optional.
3. Click **Create**.

## Browse containers

Open **Containers** in the sidebar. The table shows name, ID, image, and status.

Long port lists collapse behind a `+N` expander. In the view options menu, you can hide exposed-only ports to show only published host mappings, or turn on **Show Swarm Task Hostnames** on Swarm hosts to display task hostnames in the list (search and sort still use Docker names). To select a range of rows on the current page, check one box and **Shift**-click another.

### Filter by Docker label

In the **Labels** filter, enter a key such as `com.example.team` (matches any value), or a key and value such as `com.example.team=media`.

To keep a container out of the default list and dashboard counts, add the `com.getarcaneapp.arcane.hidden=true` label, or set `x-arcane.hidden` in Compose. See [Hide containers](/docs/reference/compose-labels#hide-containers) for examples, project-wide defaults, and unhiding.

## Start, stop, restart, pause, kill

| Action                             | What it does                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Start** / **Stop** / **Restart** | Changes the running state.                                                                                                     |
| **Pause** / **Unpause**            | Suspends and resumes all processes in the container. Needs `containers:pause`.                                                 |
| **Kill**                           | Sends a signal to the container's main process. Needs `containers:kill`.                                                       |
| **Redeploy**                       | Pulls the latest image and recreates the container in place, with the same name, mounts, labels, networks, and restart policy. |

On Podman, Quadlet containers show a **Quadlet** badge. Start, stop, and restart go to their systemd unit. Arcane won't edit, redeploy, or remove them. See [Quadlets](/docs/podman/quadlets#containers-that-belong-to-a-quadlet).

## Edit a container

1. Open a container's detail page or row menu and choose **Edit**.
2. Change the image, ports, mounts, variables, restart policy, networks, resource limits, or Linux capabilities. Network options include static IPv4 addresses and aliases.
3. Apply and confirm. Arcane **recreates** the container, so it gets a new container ID.

Editing requires `containers:update`, and changing network connections also needs `networks:connect` and `networks:disconnect`. Existing mount options are preserved, and the new image is only pulled if it isn't already on the host. If recreation fails, Arcane restores the original container unless it was configured to auto-remove.

## Convert a container to a Compose project

This feature is experimental.

1. Click the version number at the bottom of the sidebar and switch on **Experimental Features**. This needs `settings:update`.
2. On a standalone container's detail page or row menu, or in bulk, choose **Convert to Compose**. This needs `projects:create`.
3. On the new-project page, check the generated bind mounts, networks, and environment values. Edit as needed.
4. Click **Create Project**.

The original containers keep running. Stop them before you deploy to avoid name and port conflicts.

To delete them instead, select **Remove original container(s) after creation**. This needs `containers:delete`. They're deleted when the project is created, before deployment, and it can't be undone.

## Commit a container to an image

1. On a container's detail page, click **Commit**. This needs `images:commit`.
2. Optional: set repository and tag, comment, author, and whether Docker skips its default pause.
3. Confirm. The image appears on **Images**.

## Inspect a container

Click a container's name or **Inspect** to open its detail view, which has tabs for configuration, network settings, mounts, and logs. On **Overview**, clicking the volume or network counts jumps straight to those tabs, and network details show assigned IPv4 and IPv6 addresses. Containers that belong to an Arcane-managed Compose project also link back to their project and include a **Compose** tab showing the root Compose file (or the included file when the service comes from a Compose `include`). That tab is read-only for Git-synced projects.

Well-known container and service labels are pretty-printed on the **Configuration** tab for readability. Sensitive environment values are masked on both **Configuration** and **Inspect**; click **Show** to reveal all of them, or **Reveal value** on **Configuration** to show a single one. Arcane treats a variable as sensitive if any `_`-separated part of its name matches words like `PASSWORD`, `SECRET`, `TOKEN`, `KEY`, or `AUTH`, or if its value looks like a URL with credentials (contains `://` and `@`). Names ending in `_FILE`, `_PATH`, or `_DIR` are never masked.

### Updates

The **Overview** tab's **Auto Update** toggle turns automatic installation on or off. Checks continue either way. For labels, and for stopping checks too, see [Per-container labels](/docs/docker/auto-updates#per-container-labels).

When a newer image exists, the header shows an **Update available** badge and an **Update** action. Updating needs `containers:autoupdate`.

## Restart unhealthy containers automatically

Auto Heal restarts running containers whose Docker healthcheck reports `unhealthy`. Containers without a healthcheck are never touched.

1. Open **Settings → Automations** and pick the agent.
2. Under **Monitoring**, turn on **Auto-Heal**. It's off by default.
3. Optional: change its schedule. The default checks every 5 minutes (`*/5 * * * *`).

| Setting                      | Default   | What it does                                                                                                                           |
| ---------------------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Max Restarts**             | 5         | Restarts allowed per container within the restart window. After that, Arcane skips the container.                                      |
| **Restart Window (minutes)** | 30        | How far back restarts are counted.                                                                                                     |
| **Auto-Heal Mode**           | `exclude` | `exclude` heals every container except the listed ones. `include` only heals listed containers and those with `com.getarcaneapp.arcane.auto-heal=true`. |
| **Auto-Heal Containers**     | None      | Comma-separated container list. Skipped in `exclude` mode, targeted in `include` mode.                                                 |

Both numbers must be at least 1. Auto Heal also skips Arcane's own container, Arcane's helper containers, and Podman [Quadlet](/docs/podman/quadlets) containers, whose systemd `Restart=` policy handles recovery.

Each restart is logged as a container restart event and sends an **Auto-Heal Restart** [notification](/docs/settings/notifications).

## Open a shell

1. Open a running container's detail view.
2. Open the **Shell** tab. This needs `containers:exec`.
3. Pick **Auto** (`bash` when the container has it, otherwise `sh`), `sh`, `bash`, `ash`, `zsh`, or enter a custom path.
4. Optional: pick a user to run the shell as, or leave it on **Container default**.

Arcane remembers your shell and user choice per Compose service (or container name), so it survives recreation. Without a saved choice, it uses your **Default Shell** preference under **Account → Preferences** (a path, `auto`, or the agent's default), falling back to the agent's **Default Shell** (**Settings → Docker**, `/bin/sh` by default).

## View logs

Open the container's **Logs** tab. Use **Search** to filter lines and the line-count menu to choose how far back to load, from **50 lines** to **All logs**. JSON and logfmt entries render as structured rows while keeping multiline messages like stack traces together, stderr lines carry a marker, and small CPU and memory monitors sit alongside the output.

Open **Display** to toggle **Auto-scroll**, **Timestamps**, **Raw output** (original line text instead of parsed rows), and **Auto-start** (stream when the tab opens). Project logs also offer **Stream labels**, which show the service name on each line.

### Download logs

Click the download icon to save a plain-text `.log` file with timestamps and all stdout and stderr Docker still keeps. The download ignores the viewer's filters and line limit, though logs already removed by Docker's log rotation won't be included.

## Remove a container

1. Click the trash icon on the container row.
2. For a running container, check **Force**, or stop it first.
3. Confirm.
