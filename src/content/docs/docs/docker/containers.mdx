## Create a container

1. Open **Containers** and click **Create Container**.
2. Enter a name and an image. Ports, volumes, environment variables, restart policy, and other fields are optional.
3. Click **Create**.

## Browse containers

Open **Containers** in the sidebar. The table shows name, ID, image, and status.

- Long port lists collapse behind a `+N` expander.
- To show only published host mappings, hide exposed-only ports in the view options menu.
- To select a range, select a row checkbox, then **Shift**-select another. This works on the current page.

### Filter by Docker label

In the **Labels** filter, enter a key such as `com.example.team` (matches any value), or a key and value such as `com.example.team=media`.

To keep a container out of the default list and dashboard counts, add the `com.getarcaneapp.arcane.hidden=true` label, or set `x-arcane.hidden` in Compose. See [Hide containers](/docs/reference/compose-labels#hide-containers) for examples, project-wide defaults, and unhiding.

## Start, stop, restart, pause, kill

| Action                             | What it does                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Start** / **Stop** / **Restart** | Changes the running state.                                                                                                     |
| **Pause** / **Unpause**            | Suspends and resumes all processes in the container. Needs `containers:pause`.                                                 |
| **Kill**                           | Sends a signal to the container's main process. Needs `containers:kill`.                                                       |
| **Redeploy**                       | Pulls the latest image and recreates the container in place, with the same name, mounts, labels, networks, and restart policy. |

On Podman, Quadlet containers show a **Quadlet** badge. Start, stop, and restart go to their systemd unit. Arcane won't edit, redeploy, or remove them. See [Quadlets](/docs/podman/quadlets#containers-that-belong-to-a-quadlet).

## Edit a container

1. Open a container's detail page or row menu and choose **Edit**.
2. Change the image, ports, mounts, variables, restart policy, networks, resource limits, or Linux capabilities. Network options include static IPv4 addresses and aliases.
3. Apply and confirm. Arcane **recreates** the container, so it gets a new container ID.

- Editing needs `containers:update`. Changing network connections also needs `networks:connect` / `networks:disconnect`.
- Existing mount options are kept.
- The new image is pulled only if it's missing locally.
- If recreation fails, Arcane restores the original. Auto-remove containers can't be restored.

## Convert a container to a Compose project

This feature is experimental.

1. Click the version number at the bottom of the sidebar and switch on **Experimental Features**. This needs `settings:update`.
2. On a standalone container's detail page or row menu, or in bulk, choose **Convert to Compose**. This needs `projects:create`.
3. On the new-project page, check the generated bind mounts, networks, and environment values. Edit as needed.
4. Click **Create Project**.

The original containers keep running. Stop them before you deploy to avoid name and port conflicts.

To delete them instead, select **Remove original container(s) after creation**. This needs `containers:delete`. They're deleted when the project is created, before deployment, and it can't be undone.

## Commit a container to an image

1. On a container's detail page, click **Commit**. This needs `images:commit`.
2. Optional: set repository and tag, comment, author, and whether Docker skips its default pause.
3. Confirm. The image appears on **Images**.

## Inspect a container

Click a container's name or **Inspect**. The detail view has tabs for configuration, network settings, mounts, and logs.

- **Overview** volume and network counts open their tabs.
- Network details show assigned IPv4 and IPv6 addresses.
- Containers in an Arcane-managed Compose project get a **Compose** tab. It shows the root Compose file, or the included file when the service comes from a Compose `include`. It's read-only for Git-synced projects.
- Project containers link to their project.

### Updates

The **Overview** tab's **Auto Update** toggle turns automatic installation on or off. Checks continue either way. For labels, and for stopping checks too, see [Per-container labels](/docs/docker/auto-updates#per-container-labels).

When a newer image exists, the header shows an **Update available** badge and an **Update** action. Updating needs `containers:autoupdate`.

## Open a shell

1. Open a running container's detail view.
2. Open the **Shell** tab. This needs `containers:exec`.
3. Pick `sh`, `bash`, `ash`, `zsh`, or enter a custom path.

Your browser remembers the choice per Compose service (or container name), so it survives recreation. Without a saved choice, Arcane uses the environment's **Default Shell** (**Settings → Docker**), which is `/bin/sh` by default.

## View logs

Open the container's **Logs** tab.

- JSON and logfmt logs render as structured rows.
- Multiline messages, such as stack traces, stay together.
- Small CPU and memory monitors show alongside.

### Download logs

Click **Download**. You get a plain-text `.log` file with timestamps and all stdout and stderr Docker still keeps.

- The download ignores the viewer's filters and line limit.
- Logs already removed by Docker's log rotation aren't included.

## Remove a container

1. Click the trash icon on the container row.
2. For a running container, check **Force**, or stop it first.
3. Confirm.
