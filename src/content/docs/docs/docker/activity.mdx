The **Activity Center** shows background operations, such as image pulls and deploys, while they run. The **Event Log** is the long-term audit trail.

## Follow an activity

1. Open the Activity Center from the sidebar or the mobile navigation bar.
2. Select an activity. The list covers every environment you can read.

Output shows the `docker` command's text and colors, as in a terminal. For projects, you can also attach to a running operation with **Watch output**. See [Projects](/docs/docker/projects).

| Status        | Meaning                                      |
| ------------- | -------------------------------------------- |
| **Queued**    | Waiting for a free slot.                     |
| **Running**   | In progress.                                 |
| **Completed** | Finished successfully.                       |
| **Failed**    | Finished with an error. The output says why. |
| **Cancelled** | Stopped before it finished.                  |

If an activity is interrupted, for example by an Arcane restart, a background check marks it **Failed** so it doesn't stay stuck in **Running**.

What Arcane tracks:

- **Images:** pulls, [builds](/docs/docker/image-builds), and update checks.
- **Projects:** pull, build, deploy, redeploy, down, restart, and destroy.
- **Containers:** start, stop, restart, redeploy, and delete.
- **System:** vulnerability scans and system prunes.

## Set retention and concurrency

1. Open **Settings → Activity**.
2. Pick the environment under **Applying settings for**. These settings are per environment.
3. Set the fields below, then save.

| Setting                       | What it does                                                                                 |
| ----------------------------- | -------------------------------------------------------------------------------------------- |
| **Retention Days**            | How long finished activities are kept.                                                       |
| **Maximum Entries**           | A hard cap on stored activity history.                                                       |
| **Concurrent Activity Limit** | How many activities run at once. Extra ones wait in **Queued**.                              |
| **Upgrade Log Retention**     | Days to keep self-upgrade log files. Default `3`. `0` keeps them forever. Cleanup runs hourly. |

## Review automation runs

This needs `jobs:list`.

1. Open **Settings → Automations**, then **Run history** for a job. Or open the environment's **History** tab under **Environments**.
2. Select a run. It shows attempts, errors, per-target results, and activity output.

- Update checks, auto updates, scans, patching, GitOps syncs, and backups also list **Steps**.
- A queued run on a remote environment shows **Waiting for environment** until the agent is reachable.
- Agents on an older Arcane version must be upgraded to report run history.
- Depending on its state, a run offers **Retry run** or **Cancel pending run**.
- For a failed, partial, or **Needs attention** run, check its output and the affected resources before you retry.

## Review the Event Log

1. Open **Events**.
2. Search, or filter by type and severity.
3. Select a row for details.

Each row shows **Severity**, **Type**, **User** when known, and **Timestamp**. Events outlive the Activity Center's history.

The log also records Docker daemon events as they arrive: container exits, out-of-memory kills, unhealthy status changes, and image, network, and volume changes. This includes actions outside Arcane, such as starting a container from the Docker CLI.
