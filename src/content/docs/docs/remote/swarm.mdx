Use Docker Swarm instead of Compose projects when an app should run on several hosts or survive a host going down. Swarm is Docker's built-in clustering mode: hosts join one cluster, and Swarm schedules, replicates, and restarts services across them.

## Get started

1. Connect each host as a [Remote Agent](/docs/remote/agents).
2. Open **Swarm → Cluster** to see each agent's Swarm role. [Initialize a Swarm](/docs/remote/swarm-cluster#initialize-a-swarm) on one if needed.
3. Add hosts with **Easy Join** from a manager's row on the Cluster page, or an agent's detail page or row menu. Arcane fills in the manager address and join token.
4. Create the app's **Configs** and **Secrets**.
5. Deploy from **Stacks**.
6. Check rollout health and logs under **Services** and **Tasks**.

## Where the data comes from

Arcane reads cluster resources from Swarm manager agents. If several of yours manage one cluster, Arcane reads through one, so each resource is listed once; the **Agent** column shows which manager. Stacks are grouped by the `com.docker.stack.namespace` service label, so stacks created outside Arcane show up too. Agents on nodes add access to each node's containers and images; services and stacks stay visible without them (see [Nodes & Agents](/docs/remote/swarm-nodes-agents)).

## Permissions and modes

- Swarm lists include only manager agents; workers appear on the **Cluster** page. Cluster actions such as unlock, token rotation, and spec updates need a **Swarm manager** agent.
- Viewing Swarm resources needs `swarm:read`. Each change needs its own permission, such as `swarm:init`, `swarm:join`, `swarm:unlock`, `swarm-nodes:update`, `swarm-services:create`, or `swarm-stacks:create`. See the [permission catalog](/docs/access/roles#permission-catalog).
