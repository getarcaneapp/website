Use Docker Swarm instead of Compose projects when an app should run on several hosts or survive a host going down. Swarm is Docker's built-in clustering mode: hosts join one cluster, and Swarm schedules, replicates, and restarts services across them.

> [!NOTE]
> To manage other hosts, connect them as [Remote Environments](/docs/remote/environments) first. Swarm pages cover every environment you can read, and each action runs in the environment of the row you act on.

## Get started

1. Open **Swarm → Cluster** to see each environment's Swarm role, and **Nodes** for the cluster's hosts.
2. Add hosts with **Easy Join** from a manager's row on the Cluster page, or an environment's detail page or row menu. Arcane fills in the manager address and join token.
3. Create the app's **Configs** and **Secrets**, deploy from **Stacks**, then check rollout health and logs under **Services** and **Tasks**.

## Where the data comes from

Arcane reads cluster resources from Swarm manager environments. If several of yours manage one cluster, Arcane reads through one, so each resource is listed once; the **Environment** column shows which manager. Stacks are grouped by the `com.docker.stack.namespace` service label, so stacks created outside Arcane show up too. Agents on nodes add access to each node's containers and images; services and stacks stay visible without them (see [Nodes & Agents](/docs/remote/swarm-nodes-agents)).

## Permissions and modes

- Swarm lists include only manager environments; workers appear on the **Cluster** page. Cluster actions such as unlock, token rotation, and spec updates need a **Swarm manager** environment.
- Viewing Swarm resources needs `swarm:read`. Each change needs its own permission, such as `swarm:init`, `swarm:join`, `swarm:nodes`, `swarm:services`, `swarm:stacks`, or `swarm:unlock`. See the [permission catalog](/docs/access/roles#permission-catalog).
