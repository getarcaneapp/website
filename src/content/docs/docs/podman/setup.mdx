Arcane connects through Podman's Docker-compatible API socket. With a rootless user's socket, Arcane and every container it creates stay rootless. Arcane detects Podman on its own and adds a **Podman** section. See [Podman Overview](/docs/podman/overview).

## Before you start

You need:

- **Podman.** Check with `podman --version`.
- **A Compose provider** for the Compose path: [podman-compose](https://github.com/containers/podman-compose) or Docker Compose. `podman compose` runs whichever one is installed. Check with `podman compose version`.
- **The Podman socket**, turned on as shown below.

## Enable the Podman socket

Pick rootless (recommended) or rootful.

- **Rootless.** Run as the user that will own Arcane's containers:

  ```bash
  systemctl --user enable --now podman.socket
  loginctl enable-linger "$USER"
  ```

  Lingering starts your user's systemd manager at boot, without an interactive login. The socket is at `/run/user/<UID>/podman/podman.sock`, or `%t/podman/podman.sock` in a user systemd unit (`%t` is the user's runtime directory).

- **Rootful.** Run:

  ```bash
  sudo systemctl enable --now podman.socket
  ```

  The socket is at `/run/podman/podman.sock`.

## Install Arcane

Use Compose, or a Quadlet so systemd starts Arcane at boot and restarts it if it exits.

<Tabs>
<TabItem label="Compose">

<Steps>

1. **Generate an encryption key.** Run this and copy the output:

   ```bash
   podman run --rm ghcr.io/getarcaneapp/manager:latest /app/arcane generate secret
   ```

2. **Create `compose.yaml`** with the file for your setup.

   Rootless (replace `<UID>` and `<GID>` with the output of `id -u` and `id -g`):

   ```yaml
   services:
     arcane:
       image: ghcr.io/getarcaneapp/manager:latest
       container_name: arcane
       user: "0:0"
       userns_mode: keep-id
       ports:
         - "3552:3552"
       volumes:
         - /run/user/<UID>/podman/podman.sock:/var/run/docker.sock
         - arcane-data:/app/data
       environment:
         - ARCANE_APP_URL=http://localhost:3552
         - ARCANE_ENCRYPTION_KEY=<your-encryption-key>
         - PUID=<UID>
         - PGID=<GID>
       security_opt:
         - label=disable
       cgroup: host
       healthcheck:
         test: ["CMD", "./arcane", "health", "--timeout", "2s"]
         interval: 10s
         timeout: 3s
         retries: 5
         start_period: 15s
       restart: unless-stopped

   volumes:
     arcane-data:
   ```

   Rootful:

   ```yaml
   services:
     arcane:
       image: ghcr.io/getarcaneapp/manager:latest
       container_name: arcane
       ports:
         - "3552:3552"
       volumes:
         - /run/podman/podman.sock:/var/run/docker.sock
         - arcane-data:/app/data
       environment:
         - ARCANE_APP_URL=http://localhost:3552
         - ARCANE_ENCRYPTION_KEY=<your-encryption-key>
         - PUID=0
         - PGID=0
       security_opt:
         - label=disable
       cgroup: host
       healthcheck:
         test: ["CMD", "./arcane", "health", "--timeout", "2s"]
         interval: 10s
         timeout: 3s
         retries: 5
         start_period: 15s
       restart: unless-stopped

   volumes:
     arcane-data:
   ```

3. **Paste your key.** Replace `<your-encryption-key>` with the key from step 1.

4. **Set the address.** Change `ARCANE_APP_URL` to the address you will open, for example `http://<host-ip>:3552`.

5. **Start Arcane.** In the folder with `compose.yaml`, run:

   ```bash
   podman compose up -d
   ```

   For rootful, run it with `sudo`.

6. **Open Arcane** at the `ARCANE_APP_URL` address and sign in as `arcane`. Arcane generates the password on first start and writes it to `/app/data/initial-admin-password`. Run `podman compose cp arcane:/app/data/initial-admin-password .` to copy the file out. Set a new password when asked.

</Steps>

`label=disable` lets Arcane use the socket on SELinux hosts. `cgroup: host` helps Arcane find its own container. Rootless uses `keep-id` so Arcane starts as root, then switches to your `PUID`/`PGID` to own the socket. To manage a projects folder, add its mount and `ARCANE_PROJECTS_DIRECTORY` as in [Installation](/docs/get-started/installation).

On Windows 11 with Podman Desktop, use the rootful file: `/run/podman/podman.sock` is the socket inside the Podman VM.

</TabItem>
<TabItem label="Quadlet">

<Steps>

1. Generate the encryption key and store it as a Podman secret:

   ```bash
   openssl rand -hex 32 | podman secret create arcane-encryption-key -
   ```

2. Print the secret and keep a copy somewhere off this host. Without it, Arcane can't decrypt its database if the Podman secret is ever lost.

   ```bash
   podman secret inspect --showsecret --format '{{.SecretData}}' arcane-encryption-key
   ```

3. Save this as `~/.config/containers/systemd/arcane.container`, creating the directory if needed:

   ```ini
   [Unit]
   Description=Arcane Manager (rootless Podman)
   Documentation=https://getarcane.app/docs/podman/setup
   Requires=podman.socket
   After=podman.socket

   [Container]
   Image=ghcr.io/getarcaneapp/manager:latest
   ContainerName=arcane
   Pull=missing
   AutoUpdate=registry
   SecurityLabelDisable=true
   PodmanArgs=--cgroupns=host

   PublishPort=3552:3552
   Volume=%t/podman/podman.sock:/var/run/docker.sock
   Volume=arcane-data:/app/data
   Secret=arcane-encryption-key,type=mount,target=/run/secrets/arcane-key,mode=0444

   Environment=ARCANE_APP_URL=http://localhost:3552
   Environment=PUID=1000
   Environment=PGID=1000
   Environment=ARCANE_ENCRYPTION_KEY_FILE=/run/secrets/arcane-key

   HealthCmd=["./arcane","health","--timeout","2s"]
   HealthInterval=10s
   HealthTimeout=3s
   HealthRetries=5
   HealthStartPeriod=15s
   Notify=healthy

   [Service]
   Restart=always
   TimeoutStartSec=900
   TimeoutStopSec=70

   [Install]
   WantedBy=default.target
   ```

   Set `ARCANE_APP_URL` to your browser's URL and `PUID`/`PGID` to your IDs (`id -u`, `id -g`). Behind a local reverse proxy, publish on `127.0.0.1:3552:3552`. `SecurityLabelDisable=true` allows socket use on SELinux hosts, `--cgroupns=host` helps Arcane find its own container, and `HealthCmd` uses exec form because the image has no shell.

4. Start Arcane and Podman's auto-update timer:

   ```bash
   systemctl --user daemon-reload
   systemctl --user start arcane.service
   systemctl --user enable --now podman-auto-update.timer
   ```

   `[Install]` already adds the service to `default.target`, so it starts at boot without `enable`.

</Steps>

To manage projects from a host folder, add a matching mount and path (see [Installation](/docs/get-started/installation)):

```ini
Volume=/opt/docker:/opt/docker
Environment=ARCANE_PROJECTS_DIRECTORY=/opt/docker
```

</TabItem>
</Tabs>

> [!WARNING]
> The Podman socket gives Arcane control of every container owned by that Linux user. Run Arcane under a dedicated unprivileged user with no unrelated workloads or files.

## Give Arcane access to systemd

Only needed for starting and stopping Quadlets, and Podman auto-update before 6.2. Everything else works without it.

1. Mount the systemd D-Bus socket into Arcane.
2. Run Arcane as a user allowed to use it.

Pick the example for your setup below.

- **Rootless**: mount the session bus at `/run/user/<UID>/bus`. `keep-id` maps your UID into the container unchanged, since the bus rejects subordinate IDs. Arcane starts as root, then switches to `PUID`/`PGID` to own the socket and bus.
- **Rootful**: units are system services only root can manage, so mount the system bus and run Arcane as root.

<Tabs>
<TabItem label="Rootless Compose">

```yaml
services:
  arcane:
    user: "0:0"
    userns_mode: keep-id
    volumes:
      - /run/user/<UID>/podman/podman.sock:/var/run/docker.sock
      - /run/user/<UID>/bus:/run/user/<UID>/bus
      - arcane-data:/app/data
    environment:
      - DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/<UID>/bus
      - PUID=<UID>
      - PGID=<GID>
```

</TabItem>
<TabItem label="Rootless Quadlet">

Add these lines to the `[Container]` section of `arcane.container`:

```ini
User=0:0
UserNS=keep-id
Volume=%t/bus:%t/bus
Environment=DBUS_SESSION_BUS_ADDRESS=unix:path=%t/bus
```

</TabItem>
<TabItem label="Rootful Compose">

```yaml
services:
  arcane:
    volumes:
      - /run/podman/podman.sock:/var/run/docker.sock
      - /run/dbus/system_bus_socket:/run/dbus/system_bus_socket
      - arcane-data:/app/data
    environment:
      - PUID=0
      - PGID=0
```

</TabItem>
</Tabs>

With [`arcane-cli`](/docs/reference/cli/install) installed, run `arcane-cli podman status` to check the Podman version, whether Arcane runs rootless, and whether systemd is reachable. If not, the reason also shows on each Quadlet's page and **Podman → Auto Update**. When `DOCKER_HOST` points to a Podman engine on another machine, Arcane won't use its local bus; run an [Arcane Agent](/docs/remote/agents) there instead.

## Restart containers after a reboot

A Quadlet restarts Arcane itself. To also restart the containers Arcane manages that use `restart: always` or `restart: unless-stopped`, enable Podman's restart service:

```bash
systemctl --user enable --now podman-restart.service
```

Arcane doesn't redeploy stopped Compose projects when it starts, so set a restart policy in each project's Compose file.

## Check that it's working

Run the commands for how you installed Arcane. The health check needs about 15 seconds after start; until then it shows `starting`.

<Tabs>
<TabItem label="Rootless Compose">

```bash
podman info --format '{{.Host.Security.Rootless}}'
systemctl --user is-active podman.socket
podman inspect arcane --format '{{.State.Health.Status}}'
```

Expect `true`, then `active`, then `healthy`.

</TabItem>
<TabItem label="Rootful Compose">

```bash
sudo systemctl is-active podman.socket
sudo podman inspect arcane --format '{{.State.Health.Status}}'
```

Expect `active`, then `healthy`.

</TabItem>
<TabItem label="Quadlet">

```bash
podman info --format '{{.Host.Security.Rootless}}'
systemctl --user is-active podman.socket arcane.service podman-auto-update.timer
podman inspect arcane --format '{{.State.Health.Status}}'
```

Expect `true`, then `active` three times, then `healthy`.

</TabItem>
</Tabs>

## Updating Arcane

With Compose, update as on Docker. With a Quadlet, `AutoUpdate=registry` makes Podman check the image tag daily and restart `arcane.service` when it changes, rolling back if the new one isn't healthy. Arcane's own update action is off here, since recreating the container would take it out of systemd's control. To check or apply now:

```bash
podman auto-update --dry-run
systemctl --user start podman-auto-update.service
```

If you pin `Image` to a version tag, change it in the Quadlet and restart the service. Arcane's updater also skips other Quadlet containers; update them with [Podman auto-update](/docs/podman/auto-update).

## Use ports 80 and 443 without root

Only root can bind ports below 1024. To let rootless containers publish HTTP and HTTPS, lower the threshold for every unprivileged user:

```bash
echo 'net.ipv4.ip_unprivileged_port_start=80' |
  sudo tee /etc/sysctl.d/99-rootless-ports.conf
sudo sysctl --system
```

This isn't needed for Arcane's own port, `3552`.
